# 币安会话与交易控制

## 两套登录

站点登录仅保护客户面板。币安 Event Contract 下单桥接另需客户本人账号的 Web 会话 `p20t` 与 `csrftoken`，且必须来自同一个已完成登录的浏览器上下文。App 弹出“新设备已授权”并不证明 Web 会话已生成。实际曾出现远程无头浏览器扫码成功提示、但没有得到可用 `p20t` 的情况；可改用本机临时可见浏览器让客户扫码，再通过 SSH 标准输入直接导入客户服务器，最后销毁临时浏览器配置。不要写入命令历史、日志、截图、源码或聊天；客户服务器私有会话文件权限 0600。会话可能过期，需要验证，不能根据 cookie 中缺失的过期字段声称固定有效期。

## 桥接与控制

本项目的桥接只监听回环地址，配对密钥独立生成并以 0600 保存。`shadow.live_api` 和 `shadow.live_worker` 当前固定连接 `127.0.0.1:8876`。Web 只放行 `/api/live` 控制请求，并要求站点登录与匹配的 HTTPS Origin；不能把配对密钥送给浏览器。live worker 只消费客户启用之后产生的新布林带观察记录。客户在面板中选金额、合约周期、方向模式和到期保护；不要把单次测试订单的参数当成自动交易参数。

当前桥接的 `configured` 模式按周期使用预置赔率参数，**不是实时逐笔报价**。币安赔率可变；提交可能被拒，不能把预置值称为当前赔率。若未来需要实时赔率，应先验证可靠的只读报价来源及字段映射，再考虑接入。观察信号的周期与客户选择的事件合约周期是两项不同设置。

## 单次真实测试订单

收到明确授权后先检查：客户会话文件存在且权限正确、桥接无待核对请求、自动交易开关状态、订单方向/金额/周期与指令完全一致。生成 preview，立即做**一次** submit；客户端超时或返回不明时查桥接账本和客户 App，不重试。仅当 `ACCEPTED_UNVERIFIED` 时可说“币安接口已受理”；不能据此说“成交成功”。记录本次请求 ID、提交时间和状态，不输出 cookie 或原始上游响应。客户在 App 中确认该订单后，才调用桥接 acknowledge；否则保持待核对阻止。

## 启动与排障

启用自动交易前确认 live 配置与图表观察数据库可读、bridge 和 worker 均运行、桥接历史没有未核对请求、控制账本没有未知/拒绝待核对状态。启用后从 `/api/live` 读回 `enabled`、策略、周期、金额、方向和保护设置，并检查自动订单数；不要把按钮点击当成启用成功。常见的 `BRIDGE_RECONCILE_REQUIRED` 是先前单次测试单仍待核对。客户确认 App 记录后 acknowledge，再由客户按其原参数重试。人工测试单不会自动写进 live worker 的订单账本。

关闭自动交易也要读回 `enabled=false`；关闭不会撤销已经提交的事件合约。真实订单与指数代理结果分别记录，最终成交和结算以客户币安账户记录为准。
