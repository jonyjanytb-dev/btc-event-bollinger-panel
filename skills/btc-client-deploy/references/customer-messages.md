# 可转发给客户及服务器 AI 的指令

把尖括号中的值替换成这次客户的真实信息。这里的“服务器 AI”指客户自己控制台里有权限执行命令的助手；它的文字回复不能代替本机 SSH 实测。

## 发给客户的第一条消息

> 请打开你自己腾讯云账号里的轻量应用服务器控制台，确认要安装程序的那台实例。先不要把服务器密码、币安密码、验证码或任何 cookie 发到聊天。把下面的第二条消息发给能操作这台实例的服务器 AI；它回复的公网 IP、SSH 用户、端口、主机指纹和公钥安装结果转发给我。

## 发给客户服务器 AI：检查并授权 SSH 公钥

> 我授权你在**我指定的这台**腾讯云轻量应用服务器上做只读检查，并为登录用户 `<SSH_USER>` 安装下面这一行 SSH **公钥**。先确认实例 ID `<INSTANCE_ID>`，报告公网 IPv4、系统版本、SSH 端口、实际登录用户、SSH 主机公钥 SHA256 指纹、内存/磁盘余量、已占用的 80/443 端口，以及腾讯云和系统防火墙的 22/80/443 入站状态。
>
> 公钥：`<SSH_PUBLIC_KEY_整行>`
>
> 请将它追加到该用户的 `~/.ssh/authorized_keys`，不要覆盖原有内容；目录权限 0700，文件权限 0600，用户归属正确。完成后只回复安装结果和上面的非敏感信息。不要在回复中输出私钥、密码、授权文件全文、cookie、验证码或云 API 密钥；不要改动现有服务、重置密码、修改防火墙或重启。若你的权限做不到，请明确指出哪一步失败，并给我控制台的操作路径。

安装后，部署者从本机使用**对应私钥**连接，并核对首次看到的主机指纹。客户服务器 AI 不需要也不应获得私钥。

## 需要网页入口时追加的消息

> 请确认这台实例可以供客户访问 HTTPS。若 443 未开放，请只增加本实例的 TCP 443 入站规则；如果证书签发或跳转需要 80，再单独增加 TCP 80。保留原有 22 与 ICMP 规则，报告修改前后规则，不重启或重装实例。若 80/443 已被现有应用占用，只报告占用者，先不要停服务。

## 发给客户：币安扫码与测试单

> 网页面板账号与币安账号是两套登录。若要连接真实交易，请由你本人在币安 App 扫描这次登录窗口里显示的二维码并完成 App 内确认；不要把币安密码、验证码或扫码后的 token 发给任何聊天。面板显示会话已导入后，真实交易仍默认关闭。若希望我代下**一笔**连接测试单，请另外明确回复品种、合约周期、方向和金额；接口回执出来后，请在币安 App 订单记录中核对该笔订单。

## 客户说“点启动但没有打开”时

先让部署者检查 `/api/live`、live worker、桥接历史和失败码。若有 `BRIDGE_RECONCILE_REQUIRED`，查看先前手动测试单是否已在客户币安 App 中核对；只有客户确认订单记录后才标记“已人工核对”。失败的启动请求未必保留客户填写的参数，解锁后让客户按原参数重试，或取得明确参数后再代开。
