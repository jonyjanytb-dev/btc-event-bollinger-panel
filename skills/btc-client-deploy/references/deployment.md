# 部署与验收

## 1. 确定源版本

默认从公开仓库的明确 Git 提交或发布标签部署，并记录提交 SHA。若用户要复制现有服务器，从其 `systemctl` 服务定义和运行进程找到实际 `ExecStart`、工作目录、配置路径和 Python 环境，再与 Git 版本比对。运行中的代码可能不同于仓库最新提交；以用户要复制的那一版为准。列出应用、图表策略、静态资源、依赖、配置结构以及数据源，但排除所有密钥、cookie、账户数据库和客户数据。

## 2. 建立客户访问

先生成**每个客户独立**的 SSH 密钥对；将公钥交给客户服务器 AI 添加到指定登录用户的 `~/.ssh/authorized_keys`，私钥留在本机。记录客户公网 IP、SSH 用户、端口、系统版本和 SSH 主机指纹；首次连接时将指纹与客户控制台或服务器 AI 报告比对。需要公网网页时检查腾讯云入站规则、主机防火墙以及现有 80/443 服务。只有 `http://IP:端口` 的场景也可以访问，但交易控制和密码登录应优先使用可验证的 HTTPS；没有域名可用 IP 证书或 SSH 隧道，具体以当前环境支持情况为准。

不要为了安装重置客户密码、关闭现有 SSH、公用 22 端口以外再开额外管理端口，或替换其现有代理。若服务器 AI 无法运行命令，让它给出控制台操作路径和只读检查结果，由拥有权限的人完成公钥安装。

## 3. 隔离部署

- 在客户家目录创建专用应用目录，分别放 `source/`、`venv/`、`data/`、`private/` 和图表观察数据库。`private/` 权限 0700；凭据、密钥和私有配置权限 0600。
- 只传经确认的代码和依赖清单。新建独立 systemd 服务：行情采集、布林带观察、站点认证、Web 面板；开启交易功能时再加本机桥接和 live worker。保留原有服务，先检查端口冲突。
- 数据源分级处理：公开数据直接配置；获准共享的只读 token 单独放客户私有配置；任何源账号交易凭据都不得复用。模拟交易和真实交易要有各自账本。
- 网关先验证站点登录，再反代到仅监听 `127.0.0.1` 的 Web。`public_origin` 与实际 HTTPS 地址完全一致；未登录访问 `/live`、`/api/live` 应跳转登录。站点密码和设备记住期限按本次客户要求设置，不沿用上位客户的账号。
- 首次启动先确认真实交易开关关闭、自动订单账本为空，再开放页面。记录替换前版本和服务状态，预备回滚。

## 4. 验收证据

按依赖顺序核对：采集服务运行 → 行情数据库在增长 → 图表策略有有效观察记录 → 面板 `/live` 与 `/api/live` 可读 → 未登录公网入口被认证网关拦截 → 交易开关初始关闭且无自动订单。若要交易，另按 [币安会话与交易控制](trading.md) 验证桥接和客户扫码会话。只报告已观察到的状态；HTTP 200、App 的“新设备已授权”和订单接口“已受理”各自证明的事情不同。

部署完成后向用户交付访问地址、站点账号获取方式、服务清单、策略版本、可选周期/金额上限、证书状态、回滚位置和仍待客户完成的操作；不要在交付消息中回显密码或 cookie。
